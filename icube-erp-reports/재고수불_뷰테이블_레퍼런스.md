## 1. 3계층 구조 — 무엇을 언제 쓰는가

재고 조회 테이블이 10종 넘게 있는 이유는 **계층이 다르기 때문**입니다. 목적에 맞는 계층을 골라야 성능과 정확도가 동시에 확보됩니다.

```
[3계층] 사전집계    VL_INVCO / VL_INVDIV / VL_INVLC / L_INVSUM_LC
                    → 연도 단위 기초/입고/출고 합계. 현재고 조회 최속.
                      단, IO_DT가 없어 "과거 특정일 기준" 조회 불가.

[2계층] 통합 뷰      VL_LINVTORY_ALL / VL_LINVTORY_LX / VL_LINV_WIP_ALL / LINVTORY_D
                    → 원장과 동일 입도 + 통합 범위. 일자별 조회 가능.

[1계층] 원장        LINVTORY(창고) / LINV_WIP(재공) / LINV_MVFIFO(평가 후)
                    → 건별 수불. 추적·검증용. 가장 느림.
```

### 선택 가이드

| 하려는 것 | 써야 할 것 | 이유 |
|---|---|---|
| 지금 현재고 (품목별) | `VL_INVDIV` | 연도 집계, 1행 조회 |
| 지금 현재고 (창고·장소별) | `VL_INVLC` | + WH_CD, LC_CD |
| 수불유형별 현재고 | **`L_INVSUM_LC`** | + `GRP_FG` 보유 |
| **과거 특정일 기준 재고** | `LINVTORY` (+`IO_DT <=`) | 집계 뷰엔 일자 없음 |
| 창고 + 실적입고 통합 재고 | **`LINVTORY_D`** | `BASELOC_CD`/`LOC_CD` 추가 |
| 재공 재고 | `VL_LINV_WIP_ALL` / `LINV_WIP` | 창고재고와 **별도 테이블** |
| 평가 반영 금액 | `LINV_MVFIFO` | 평가 후 단가·금액 |
| 평가 차이 검증 | `LINV_MVFIFO_WK` | `*_AM_GAP` 컬럼 보유 |
| 기간 평가 단가 | `LINV_TAV` | `GISU`+`SMM`~`FMM` 키 |

## 2. 테이블·뷰 명세

### 2-1. 수불 원장 계열 (동일 컬럼셋)

`LINVTORY` / `VL_LINVTORY_ALL` / `VL_LINVTORY_LX` / `LINV_WIP` / `VL_LINV_WIP_ALL`

| 컬럼 | 의미 | 컬럼 | 의미 |
|---|---|---|---|
| `CO_CD` | 회사 | `IO_DT` | 수불일자 |
| `INV_NB` / `INV_SQ` | 수불번호 / 순번 | `P_YR` | 회계연도 (파티션 키) |
| `ITEM_CD` | 품번 | `MGMT_QT` | 관리단위 수량 |
| `IO_FG` | 입출구분 0.기초 1.입고 2.출고 | `INV_UM` / `INV_AM` | 단가 / 금액 |
| `GRP_FG` | 수불그룹 (아래 3장) | `TR_CD` | 거래처 |
| `TYP_FG` | 유형구분 | `WO_CD` | 작업지시번호 |
| `IOPEN_QT` | 기초수량 | `ITEMPARENT_CD` | 모품목 |
| `IRCV_QT` | 입고수량 | `WH_CD` / `LC_CD` | 창고 / 장소 |
| `IISU_QT` | 출고수량 | `LOT_NB` / `PJT_CD` | LOT / 프로젝트 |
| `IO_QT` | 수불수량 | `EMP_CD` / `DEPT_CD` / `DIV_CD` | 사원 / 부서 / 사업장 |
| `USE_YN` / `EXPIRE_YN` | 사용 / 유효 ('1'=유효) | `DUMMY1~3` | 예비 |

**`LINVTORY_D`** = 위 컬럼 + **`BASELOC_CD`, `LOC_CD`**
→ *"창고 + (작업실적입고 / 일괄생산실적(창고)) 총괄"*. 생산입고분까지 한 테이블에서 보려면 이쪽.

### 2-2. 사전집계 뷰

| 뷰 | 키 | 값 |
|---|---|---|
| `VL_INVCO` | `P_YR + CO_CD + ITEM_CD` | `IOPEN` / `IRCV` / `IISU` |
| `VL_INVDIV` | + `DIV_CD` | 〃 |
| `VL_INVLC` | + `WH_CD` + `LC_CD` | 〃 |
| **`L_INVSUM_LC`** | + **`GRP_FG`** | 〃 |

```sql
-- 현재고 (가장 빠른 방법)
SELECT ITEM_CD, ISNULL(IOPEN,0) + ISNULL(IRCV,0) - ISNULL(IISU,0) AS 현재고
FROM   VL_INVDIV
WHERE  P_YR = '2026' AND CO_CD = '1000' AND DIV_CD = '1000';
```

> `L_INVSUM_LC`는 `GRP_FG`를 포함하므로 **"구매입고분 재고 / 생산입고분 재고"를 분리**할 수 있습니다. 앞서 `LX_BOM_BACK_INVTORY`가 출고를 `PISU/SISU/EISU`로 3분할했던 것과 같은 발상이며, **이쪽은 iCUBE 표준 제공본**입니다.

### 2-3. 평가 계열

| 테이블 | 성격 | 주요 컬럼 |
|---|---|---|
| `LINVTORY` | 평가 **전** 수불 | `IOPEN_QT` / `IRCV_QT` / `IISU_QT` |
| `LINV_MVFIFO` | 평가 **후** 재고자산수불부 | `GISU`, `SMM`, `FMM`, `CLS_NB`, `IO_NB`, `IO_SQ`,<br>`OPEN_QT/AM`, `RCV_QT/AM`, `RCVT_QT/UM/AM`,<br>`ISU_QT/UM/AM`, `TRNS_QT/UM/AM`, `INV_QT/AM` |
| `LINV_MVFIFO_WK` | 평가 작업본 | 위 + **`OPEN_AM_GAP`, `RCV_AM_GAP`, `RCVT_AM_GAP`** (차이금액) |
| `LINV_TAV` | 기간 평가 결과 | `GISU` + `SMM` + `FMM` + `ITEM_CD` → `ISU_UM`, `MGMT_QT` |

**`LINV_TAV` 조인 키에 `GISU`(기수)가 포함**됩니다. 누락하면 과거 기수 데이터가 중복 조인됩니다.

```sql
LEFT OUTER JOIN LINV_TAV T
  ON  T.CO_CD = W.CO_CD AND T.DIV_CD = W.DIV_CD
  AND T.GISU  = W.GISU  AND T.SMM = W.SMM AND T.FMM = W.FMM
  AND T.ITEM_CD = W.ITEM_CD
```

### 2-4. 집계 헬퍼 뷰 ★ — 잔량 계산을 단순하게

| 뷰 | 원천 | 키 | 값 | 용도 |
|---|---|---|---|---|
| **`VL_SO_ISU`** | `LDELIVER_D` | `CO_CD + SO_NB + SO_SQ` | `ISU_QT` 합계 | 출고 원장 재집계 (대사·검증용) |
| **`VL_RCV_CLS`** | `LPURCLS_D` | `CO_CD + RCV_NB + RCV_SQ` | `CLS_QT` 합계 | 입고 미마감분 |
| **`VL_SLSCLS`** | `LSALECLS_D` | `CO_CD + ISU_NB + ISU_SQ` | — | 출고 마감여부 |
| **`VL_LWO_REQ_WF`** | 지시 자재 | — | 청구/투입/사용 | M-05 그대로 대체 |

> **수주잔량은 `LSO_D.ISU_QT`가 정답입니다.** 이 컬럼은 **주문등록 대비 출고현황을 추적하기 위해 ERP가 관리하는 정식 필드**이며, 수주잔량 = `SO_QT - ISU_QT` 가 표준 산식입니다. `원자재수급총괄현황_MRP.sql`의 현재 구현이 맞으므로 **변경하지 않습니다.**
>
> `VL_SO_ISU`는 같은 값을 출고 원장(`LDELIVER_D`)에서 재집계한 뷰이므로, **잔량 계산의 대체가 아니라 데이터 정합성 대사용**으로 쓰는 것이 맞습니다 (부록 A).

## 3. 수불 분류 체계 — 완전 매트릭스

### 3-1. `IO_FG` (입출구분)

```
0.기초    1.입고    2.출고
```

### 3-2. `GRP_FG` (수불그룹)

| 값 | 의미 |
|---|---|
| `0` | 생산입고 / 생산자재출고 / 일괄생산실적 |
| `2` | 구매입고 |
| `3` | 매출출고 |
| `5` | 재고이동 (사업장간 등) — **생산자재 집계 시 제외 대상** |
| `6` | 재고조정 / 해체조정 / 기초이월 |

### 3-3. `GRP_FG` × `IO_FG` × `CLS_NB` 전체 매트릭스

| GRP_FG | IO_FG | CLS_NB | 업무 | 수불NB(`IO_NB`) | 대상 계정 |
|:---:|:---:|---|---|---|---|
| 0 | 1.입고 | `IW%` | 생산 > 작업실적입고 | `WR%`실적 / `WO%`지시 | 제품·반제품 |
| 0 | 1.입고 | `MF%` | 일괄생산실적 (상단) | 사용자임의 | 제품·반제품 |
| 0 | 2.출고 | `MV%` `MB%` | 생산자재출고처리 | | 원·부재료·반제품 |
| 0 | 2.출고 | `MF%` | 일괄생산실적 (하단) | 사용자임의 | 원·부재료·반제품 |
| 2 | 1.입고 | `PC%` | 구매 > 매입마감 | `RV%` `RB%` 입고처리 | 원·부재료·상품 |
| 3 | 2.출고 | `SC%` | 영업 > 매출마감 | `IS%` `IB%` 출고처리 | 제품·상품 |
| 6 | 0.기초 | `IA%` | 재고조정 (기초) | | 전체 |
| 6 | 1.입고 | `IA%` | 재고조정 (입고) | | 전체 |
| 6 | 1.입고 | `DJ%` | 해체조정 (하단=대체입고) | | 전체 |
| 6 | 2.출고 | `IA%` | 재고조정 (출고) | | 전체 |
| 6 | 2.출고 | `DJ%` | 해체조정 (상단=대체출고) | | 전체 |
| 6 | 0.기초 | `XY%` | 재고/재공 이월기초 (연말 자동) | | 전체 |
| — | — | `OW%` | 기초재공등록 | | 재공 |
| — | — | `WI%` `WM%` `WA%` | 재공입고 / 재공이동 / 재공조정 | | 재공 |

> **`CLS_NB`(수불번호)는 사용자 임의 입력이 가능**합니다. 접두어 매칭(`LIKE 'MV%'`)이 100% 보장되지 않으므로, **`GRP_FG` + `IO_FG` 조합을 1차 기준으로 쓰고 `CLS_NB`는 보조**로 쓰는 것이 안전합니다.

### 3-4. 완제품(`ACCT_FG='2'`) 입출고 유형 판정

검증된 `CASE` 패턴입니다.

```sql
CASE WHEN GRP_FG='0' AND IO_FG='1' THEN '생산입고'
     WHEN GRP_FG='0' AND IO_FG='2' THEN '생산출고'
     WHEN GRP_FG='3' AND IO_FG='2' THEN '매출출고'
     WHEN GRP_FG='2' AND IO_FG='1' THEN '구매입고'
     WHEN GRP_FG='6' AND IO_FG='1' THEN '대체입고'
     WHEN GRP_FG='6' AND IO_FG='2' THEN '대체출고' END
```

### 3-5. 재공처리 `LWIPIO.MAP_FG`

| 값 | 의미 | 값 | 의미 |
|:---:|---|:---:|---|
| 1~3 | 실적별(실적품목) 재공입고/이동/조정 | 7~9 | 예외 재공입고/이동/조정 |
| 4~6 | 지시별(투입자재) 재공입고/이동/조정 | | |

## 4. 이전 산출물 대비 정정·보강 사항

### 4-1. 생산자재출고 필터 — 목적에 따라 두 가지 ⚠️

앞서 "생산자재출고 = `IO_FG='2' AND GRP_FG='0'`"으로 확정했는데, 자료마다 조건이 다릅니다. **둘 다 맞고, 목적이 다릅니다.**

| 조건 | 범위 | 쓰는 곳 |
|---|---|---|
| `IO_FG='2' AND GRP_FG='0'` | 생산자재출고만 | **원가 재료비** (정확) |
| `IO_FG='2' AND GRP_FG<>'5'` | 재고이동 제외 전체 출고 | 자재 총출고 검증 |

→ 원가 보고서의 `#MTL_ISU`는 `GRP_FG='0'`이 맞습니다. 다만 **대체출고(`GRP_FG='6'`)로 처리된 자재 투입이 있는 사이트**에서는 누락되므로, 아래로 먼저 확인하십시오.

```sql
SELECT H.GRP_FG, H.IO_FG, COUNT(*) 건수, SUM(D.MOVE_QT) 수량
FROM   LSTKMOVE H INNER JOIN LSTKMOVE_D D ON D.CO_CD=H.CO_CD AND D.MOVE_NB=H.MOVE_NB
WHERE  H.CO_CD='1000' AND ISNULL(D.WO_CD,'') <> ''
GROUP BY H.GRP_FG, H.IO_FG ORDER BY 1,2;
```

### 4-2. `SETITEM_FG` (SET품여부) — 완제품 세분류

```sql
CASE WHEN ACCT_FG='2' AND SETITEM_FG='1' THEN '세트완제품'
     WHEN ACCT_FG='2' AND SETITEM_FG='0' THEN '완제품'
     WHEN ACCT_FG='0' THEN '원재료' WHEN ACCT_FG='1' THEN '부재료'
     WHEN ACCT_FG='4' THEN '반제품' WHEN ACCT_FG='5' THEN '상품' END
```

세트품은 BOM 전개·원가 배부 방식이 다를 수 있어 **분리 집계가 필요**합니다. EIS 문서의 모든 재고·원가 항목에 이 구분을 추가하는 것이 좋습니다.

### 4-3. `S_CD <> 'Z00'` 관례 ★

여러 실무 쿼리가 공통으로 `ISNULL(S_CD,'') <> 'Z00'`을 겁니다. **소분류 `Z00` = 사용중지(단종) 품목** 관례입니다. 빼지 않으면 단종품이 재고·소요 리스트를 오염시킵니다.

```sql
SELECT S_CD, COUNT(*) FROM SITEM WHERE CO_CD='1000' GROUP BY S_CD ORDER BY 2 DESC;
```

### 4-4. 관리구분 `LCTRL_MGM_D` + `CTRL_CD`

재고조정 사유 등 관리구분 명칭 조회용입니다.

```sql
LEFT OUTER JOIN LCTRL_MGM_D M
  ON M.CO_CD = D.CO_CD AND M.MGM_CD = D.MGMT_CD
WHERE M.CTRL_CD = 'LA'      -- LA = 재고조정 관리구분
```

`CTRL_CD`는 모듈·업무별 구분자입니다 (`LA` 재고조정, `LP` 구매자재, `LS` 영업 …). **`CTRL_CD` 조건을 빼면 다른 업무의 관리구분과 중복 조인**됩니다.

### 4-5. 재고 조회 3대 함정 (재확인)

1. **연도 파티션** — `P_YR` 필수. 연초에는 전년 이월(`GRP_FG='6'`, `CLS_NB='XY%'`)이 넘어왔는지 확인.
2. **재공 분리** — 창고재고(`LINVTORY`)와 재공(`LINV_WIP`)은 별개. 통합 시 `BASELOC_FG`(0.창고/1.공정)로 구분.
3. **`MGMT_QT` vs `IO_QT`** — 관리단위와 재고단위가 다르면 `SITEM.UNITCHNG_NB`(환산계수)로 환산 필요.

## 5. EIS 문서 반영

| EIS 항목 | 변경 |
|---|---|
| **P-03** 실시간 재고추적 | 원장 직접집계 → **`VL_INVLC` / `L_INVSUM_LC` 우선**, 과거일 조회 시에만 `LINVTORY` |

| **P-08** MRP | 수주잔량은 `LSO_D.ISU_QT` 유지 (정식 필드). `VL_SO_ISU`는 대사용 |
| **M-04** 공정별 재공 | `VL_LINV_WIP_ALL` 우선 |
| **M-05** 자재 청구/출고/사용 | **`VL_LWO_REQ_WF`** 뷰가 있으면 통째로 대체 가능 |

| **전체** | `SETITEM_FG` 구분, `S_CD<>'Z00'` 필터 기본 적용 |

## 부록 A. 수주잔량 — 표준 산식과 정합성 대사

**표준 산식 (변경 불필요)**

```sql
수주잔량 = LSO_D.SO_QT - LSO_D.ISU_QT
```

`LSO_D.ISU_QT`는 **주문등록 대비 출고현황 추적용으로 ERP가 관리하는 정식 필드**입니다.
MRP·수주진행현황·주문미납현황 등 잔량이 필요한 모든 현황은 이 컬럼을 그대로 씁니다.
(실무 쿼리들도 `LSO_D.SO_QT - ISNULL(LDELIVER_D.SO_QT,0) > 0` 또는 `SO_QT - ISU_QT` 형태로 동일)

**정합성 대사 (운영 점검용)**

`VL_SO_ISU`는 같은 값을 출고 원장에서 재집계한 뷰입니다. 두 값이 어긋나면 출고 반영 이상이므로,
**정기 데이터 점검 항목**으로 돌려볼 가치가 있습니다.

```sql
SELECT D.SO_NB, D.SO_SQ, D.ITEM_CD, D.SO_QT,
       D.ISU_QT AS 요약컬럼, V.ISU_QT AS 원장집계,
       D.ISU_QT - ISNULL(V.ISU_QT,0) AS 차이
FROM   LSO_D D LEFT OUTER JOIN VL_SO_ISU V
       ON V.CO_CD=D.CO_CD AND V.SO_NB=D.SO_NB AND V.SO_SQ=D.SO_SQ
WHERE  D.CO_CD='1000' AND ISNULL(D.ISU_QT,0) <> ISNULL(V.ISU_QT,0);
```

> 반품·부분출고 취소 등으로 정상적인 차이가 날 수 있습니다. 차이 건이 나오면 곧바로 오류로
> 단정하지 말고 해당 수주의 출고 이력을 먼저 확인하십시오.

## 부록 B. 도입 전 확인

```sql
-- 제공 뷰 실존 확인 (사이트마다 다름)
SELECT name, create_date FROM sys.views
WHERE name IN ('VL_LINVTORY_ALL','VL_LINVTORY_LX','VL_LINV_WIP_ALL','LINVTORY_D',
               'VL_INVCO','VL_INVDIV','VL_INVLC','L_INVSUM_LC',
               'VL_SO_ISU','VL_RCV_CLS','VL_SLSCLS','VL_LWO_REQ_WF','LINVHG')
UNION ALL
SELECT name, create_date FROM sys.tables
WHERE name IN ('LINVTORY','LINVTORY_D','LINV_WIP','LINV_MVFIFO','LINV_MVFIFO_WK',
               'LINV_TAV','LWIPIO','L_INVSUM_LC')
ORDER BY name;

-- 집계뷰 vs 원장 정합성 (같아야 정상)
SELECT V.ITEM_CD, V.IOPEN+V.IRCV-V.IISU AS 뷰기준,
       L.QT AS 원장기준, (V.IOPEN+V.IRCV-V.IISU) - L.QT AS 차이
FROM   VL_INVDIV V
INNER JOIN (
    SELECT ITEM_CD, SUM(ISNULL(IOPEN_QT,0)+ISNULL(IRCV_QT,0)-ISNULL(IISU_QT,0)) QT
    FROM   LINVTORY WHERE CO_CD='1000' AND DIV_CD='1000' AND P_YR='2026'
    GROUP BY ITEM_CD
) L ON L.ITEM_CD = V.ITEM_CD
WHERE  V.CO_CD='1000' AND V.DIV_CD='1000' AND V.P_YR='2026'
  AND  (V.IOPEN+V.IRCV-V.IISU) <> L.QT;
```
