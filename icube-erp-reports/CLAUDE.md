# CLAUDE.md — iCUBE ERP 리포트 개발 프로젝트

> 이 파일은 **Claude Code가 이 프로젝트를 이어받을 때 먼저 읽는 문서**다.
> 실 DB 테스트·수정 단계에서 반드시 지켜야 할 확정 사항과 판단 근거를 담았다.

---

## 1. 이 프로젝트가 무엇인가

**더존 iCUBE ERP**(MS-SQL Server, DB명 보통 `DZICUBE`)의 **EIS/KPI 리포트 쿼리 46개**다.
영업·구매자재·생산·원가·회계 5개 모듈의 현황/KPI/점검 리포트를 T-SQL로 구현했다.

- **개발 완료** — 로드맵(1~4차 + 상시) 및 잔여 항목 전체. 미개발 0건
- **정적 검사 통과** — `tools/lint_icube_sql.py` 기준 **error 0**.
  DB 없이 잡을 수 있는 오류(코드값 전제 위반, 기수 누락, NOLOCK 누락, 한글 인코딩)는 정리했다
- **현재 단계** — **실 DB 미검증.** 문법·규약은 정적 검사로 걸렀으나 **실행 테스트는 여전히 하지 않았다.**
  검사가 통과했다는 것은 "규약을 지켰다"는 뜻이지 "숫자가 맞다"는 뜻이 아니다
- **다음 할 일** — 실 DB 적용, 오류 수정, 사이트 특성 반영

### 작업 시 기본 자세

- 이 산출물은 **여러 사이트에 재사용**할 것을 전제로 만들었다. 특정 사이트 값을 하드코딩하지 말고 파라미터로 뺄 것
- 명세서에 없는 테이블이 많다. **`OBJECT_ID` 가드 + 동적 SQL**로 없어도 죽지 않게 하는 것이 이 프로젝트의 규칙이다
- 결과가 비면 대개 **코드값을 반대로 건 것**이다. 2장을 먼저 볼 것

## 2. ★★ 확정 코드값 — 전 파일의 전제

실무 쿼리·API 규약서·원가 SP 교차 검증으로 확정했다. **바꾸려면 근거가 있어야 한다.**

## 3. 핵심 조인 체계

```
[O2C]  수주 LSO/LSO_D
         → LWO_WF (SO_NB + LN_SQ)          작업지시  ★ 수주 직결
         → LORCV_H (WO_CD)                 생산실적
         → LPRDINWH (WR_CD)                실적입고
         → LDELIVER_D (SO_NB + SO_SQ)      출고      ★ 수주 직결
         → LSALECLS_D (ISU_NB + ISU_SQ)    매출마감
         → ADOCUH (DOCU_DT + DOCU_SQ)      전표
         → LRCP_D (ISU_NB + ISU_SQ)        수금

[자재]  SBOM_WF
         → LWO_REQ_WF (WO_CD + WOBOM_SQ)   자재청구
         → LSTKMOVE_D                      자재출고
         → LMTL_USE (WR_CD + WOBOM_SQ)     사용보고

[P2P]  LPUR_REQ_D (REQ_NB + REQ_SQ)        청구
         → LPO_D                           발주
         → LSTOCK_D (PO_NB + PO_SQ)        입고
         → LPURCLS_D (RCV_NB + RCV_SQ)     매입마감

[채권]  LOPN_CRISU(출고기준) / LOPN_CRISU_CLS(마감기준) + LCR_ADJUST
        여신한도 = LCR_LIMIT (없으면 STRADE.CREDIT_AM)
```

### 사용자가 확정해 준 사항 (중요)

1. **`LSO_D.ISU_QT`는 정식 필드다.** "주문등록 대비 출고현황을 위한 출고수량"이며,
   수주잔량 = `SO_QT - ISU_QT` 가 **표준 산식**이다. `VL_SO_ISU`(출고원장 재집계)는 대사용.
   → 이 필드를 "요약 컬럼이라 부정확"으로 격하하지 말 것. 개발 중 그렇게 썼다가 정정받았다.

2. **미수채권은 출고기준·마감기준 둘 다 있고, 최종은 마감기준이다.**
   - 마감기준 = `LSALECLS_D.CLSH_AM` ← **최종**
   - 출고기준 = `LDELIVER_D.ISUH_AM` ← 선행지표
   - 차이 = **미마감 채권** (회계 미확정분, 마감 누락 통제 지표)

3. **외주가공비 소스는 `LOCLS_H`/`LOCLS_D`다.** `LWO_WF_D.LBR_AM`(지시상 예정치)이 아니다.
   원가계산 SP(`USP_COT0010_CALC_COST_TAV`) 5-4 단계가 쓰는 테이블이 이것이다.

## 4. 개발 중 바로잡은 오류 — 같은 실수 반복 금지

| # | 잘못 | 바로잡음 | 근거 |
|---|---|---|---|
| 1 | `EXPIRE_YN IN ('0','N')`을 진행으로 | `='1'`이 진행 | API 연동규약서 |
| 2 | MRP 에서 또 반대로 (`<> '1'`) | `='1'` | UDR 쿼리 8건 교차검증 |
| 3 | 외주비를 `LWO_WF_D.LBR_AM`에서 | `LOCLS_H/D` | 원가 SP 5-4 |
| 4 | 자기품목 투입 미제외 | `H.ITEM_CD <> D.ITEM_CD` | 원가 SP 5-2 |
| 5 | `SBOM.BATCH_QT`로 나눔 | BATCH BOM 은 `SBOM_WF_B` + `SITEM.FOQ_QT` | 별도 테이블 확인 |
| 6 | 청구 테이블을 `LWOBOM`으로 추정 | 실제 `LWO_REQ_WF` | 실무 쿼리 |
| 7 | UDR 코퍼스를 "혼재"로 분류 | 전부 ERP-X (LWO_WF 0건 / LWO 15건) | 실측 |
| 8 | `SDEPT.USE_YN` 사용 | 그 컬럼 없음 (REG_DT/TO_DT로 관리) | 명세서 |
| 9 | 수금에 모듈 필터 없음 | `RCPAM_FG='0'` 추가 | 실무 쿼리 |
| 10 | 여신을 `STRADE.CREDIT_AM`만 | `LCR_LIMIT` 우선 | INSERT 스크립트 |
| 11 | P-07 에 의도적으로 0 나오는 컬럼 | 제대로 계산되게 수정 | 자체 수정 |
| 12 | `LINV_TAV` 를 기수(`GISU`) 없이 조회 | `(@p_GI IS NULL OR GISU=@p_GI)` 추가 | 2장 전제 · C-06 패턴 |
| 13 | A-02 수금에 `RCPAM_FG` 필터 없음 | `='0'` 추가 (오류 #9 재발) | S-04·S-06·E-01·A-05 |
| 14 | 실테이블 11곳에 `WITH (NOLOCK)` 누락 | 전부 추가 | 작성 규칙 9 |
| 15 | 전 파일 UTF-8 BOM 없음 | BOM 추가 | SSMS 가 CP949 로 읽어 한글 깨짐 |

12~15 는 정적 검사기가 전수로 찾아낸 것이다. 같은 부류가 다시 들어오면 `tools/lint_icube_sql.py`
가 잡는다. **고친 뒤에는 반드시 검사를 다시 돌릴 것.**

## 6. 모든 파일이 지키는 작성 규칙

수정할 때도 이 규칙을 유지할 것.

1. **구조** — 헤더 주석(목적·소스·산식·주의) → 파라미터 → 임시테이블 적재 → 쿼리 A~H → [도입 전 확인] → [한계] → [관련 산출물]
2. **파라미터** — 상단 `DECLARE` 한 곳에 모은다. 사이트 값은 여기만 바꾸면 되게
3. **가드** — 명세서 누락 테이블은 `OBJECT_ID(N'dbo.X', N'U') IS NOT NULL` 확인 후 동적 SQL
4. **컬럼 자동 탐색** — 사이트별 차이가 큰 테이블은 `sys.columns`로 후보를 찾고, 실패 시 조용히 생략하되 점검 쿼리에 `(미확인)` 표시
5. **집계 후 조인** — 1:N 관계는 반드시 미리 집계한 뒤 LEFT JOIN. 직접 조인하면 금액이 부풀려진다
6. **판정 컬럼** — 숫자만 내지 말고 `판정`/`조치` 컬럼으로 무엇을 할지 제시. `★` 접두는 문제 항목
7. **[도입 전 확인]** — 파일 하단에 사이트 첫 적용 시 돌릴 확인 쿼리를 반드시 넣는다
8. **[한계]** — 이 리포트로 알 수 없는 것을 정직하게 쓴다. 근사치는 근사치라고 명시
9. **NOLOCK** — 조회 전용이므로 `WITH (NOLOCK)` 사용
10. **한글 별칭** — 결과 컬럼은 한글. 현업이 그대로 본다
11. **요구 엔진 선언** — 2012 전용 구문을 쓰면 헤더 `DBMS :` 줄에 `MS-SQL Server 2012 이상` 이라고 쓴다.
    쓰지 않으면 `ENV002` 가 error 로 잡는다 (9장 참조)

## 7. 실 DB 테스트 시 작업 순서

```
⓪ python3 tools/lint_icube_sql.py  ← DB 없이 되는 것부터. error 0 을 확인하고 시작
① Z00_사이트진단.sql 실행          ← 0단계 엔진 버전부터 본다. 판정 매트릭스 확보
② 사이트적용_체크리스트.md C단계    ← 코드값 전제 확정
     EXPIRE_YN 이 반대로 나오면 → python3 tools/flip_expire_yn.py  (미리보기)
                                   python3 tools/flip_expire_yn.py --apply
③ 진단 출력 [3] 의 'O 사용가능' 부터 순서대로 실행
④ 오류 발생 시 아래 우선순위로 확인
⑤ 수정 후 해당 파일의 [도입 전 확인] 블록도 함께 갱신
⑥ python3 tools/lint_icube_sql.py  ← 수정이 규약을 깨지 않았는지 재확인
```

### 오류 발생 시 확인 우선순위

0. **구문 오류 (`OVER` / `LAG` / `ROWS BETWEEN` 근처)** — 컬럼 문제가 아니라 **엔진이 2008 R2** 다.
   Z00 출력 [1] 의 0단계를 볼 것. 파일을 고칠 게 아니라 실행할 서버를 바꿔야 한다
1. **컬럼명 불일치** — 가장 흔하다. `sys.columns`로 실제 컬럼을 보고 파일의 후보 목록에 추가
2. **테이블 없음** — 가드가 있으면 조용히 생략된다. 가드가 없어 오류가 나면 가드를 추가
3. **결과가 빔** — `EXPIRE_YN` 방향, 기간 파라미터, 구분코드(`@EXP_SOFG`/`@DOC_FG`/`@EXP_FG`) 순으로 확인
4. **금액이 이상** — 부가세 포함 컬럼(`CLSH_AM`)을 공급가(`CLSG_AM`) 자리에 쓰지 않았는지
5. **행이 부풀려짐** — 집계 후 조인 원칙을 어긴 곳이 있는지

### 수정 후 반드시 할 것

- **`python3 tools/lint_icube_sql.py` 를 돌린다.** error 가 남으면 실 DB 에 올리지 않는다
- 같은 패턴이 다른 파일에도 있으면 **함께 수정**한다 (예: 컬럼명 변경, 코드값 해석).
  전 파일에 걸친 수정은 손으로 하지 말고 도구를 쓰거나 만들 것 — 46개는 반드시 빠뜨린다
- `모듈별_리포트_개발목록.md`에 변경 이력을 남긴다
- 코드값 해석이 바뀌면 **이 CLAUDE.md 2장을 갱신**한다

## 9. 환경

- **DBMS** — MS-SQL Server

  **46개 중 24개가 SQL Server 2012 이상을 요구한다.** iCUBE 신규 설치는 2012 지만
  오래된 사이트는 2008 R2 로 남아 있고, 거기서는 아래 구문이 **구문 오류**로 거부된다.
  호환성 수준(compatibility level)과는 별개 축이다 — 엔진이 2008 R2 면 compat 을
  아무리 올려도 안 된다.

  | 구문 | 쓰는 곳 | 2008 R2 |
  |---|---|---|
  | `LAG()` / `LEAD()` | 전기 대비 증감 | 함수 없음 |
  | 집계 + `OVER(ORDER BY …)` | 누적합·누적비율 | `PARTITION BY` 만 허용 |
  | `ROWS`/`RANGE BETWEEN` 프레임 | 이동평균·누계 | 프레임 절 자체가 없음 |
  | `PERCENTILE_CONT()` | 중앙값·사분위 | 함수 없음 |
  | `EOMONTH()` | 월말일 | 함수 없음 |

  어느 파일이 걸리는지는 **헤더 `DBMS :` 줄**에 적혀 있고, `ENV002` 규칙이 헤더와
  실제 코드가 어긋나면 error 로 잡는다. `Z00_사이트진단.sql` 의 0단계도 같은 목록을
  들고 있어, 2008 R2 사이트에서는 해당 리포트를 `X 엔진버전` 으로 판정한다.
  세 곳이 어긋나지 않는지는 `tests/test_icube_sql_rules.py` 가 잠근다.

  **호환성 수준이 90 미만(80, SQL 2000 모드)이면** 엔진과 무관하게 `OVER()` ·
  `CROSS/OUTER APPLY` · CTE · `EXCEPT` 가 전부 막힌다. 0단계가 이것도 본다.

  2008 R2 사이트의 선택지는 셋이다 — ⓐ 엔진 업그레이드, ⓑ 2012+ 인스턴스에
  리포팅 복제본을 두고 거기서 실행, ⓒ 22개만 사용. **ⓑ 가 대체로 가장 싸다**
  (운영 DB 를 건드리지 않으므로 ERP 벤더 인증 문제가 없다).
- **문자셋** — 전 파일 한글 포함. `N'...'` 유니코드 리터럴 사용
- **실행** — SSMS 또는 Azure Data Studio. 파일 단위로 전체 실행하면 쿼리 A~H가 순차 출력됨
- **UDR 연동** — 사용자정의메뉴로 올릴 때는 `사용자정의메뉴_작성가이드.md` 참조
  (`@@회사`/`@라벨` 치환 규칙, 텍스트 DSL `:[00]` 방식)
