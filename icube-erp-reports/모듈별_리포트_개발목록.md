### B-01 스코어카드 산식 (제안)

```sql
SELECT 항목, 전체, 미등록,
       CAST(100.0*(전체-미등록)/NULLIF(전체,0) AS DECIMAL(5,1)) AS 등록률
FROM (
  SELECT '조달일수(LEAD_DT)'  항목, COUNT(*) 전체, SUM(CASE WHEN ISNULL(LEAD_DT,0)=0      THEN 1 ELSE 0 END) 미등록 FROM SITEM WHERE CO_CD=@CO AND USE_YN='1' AND ACCT_FG IN ('0','1')
  UNION ALL SELECT '안전재고',      COUNT(*), SUM(CASE WHEN ISNULL(SAFESTOCK_QT,0)=0       THEN 1 ELSE 0 END) FROM SITEM WHERE CO_CD=@CO AND USE_YN='1' AND ACCT_FG IN ('0','1')
  UNION ALL SELECT '구매단가',      COUNT(*), SUM(CASE WHEN ISNULL(PURCH_UM,0)=0           THEN 1 ELSE 0 END) FROM SITEM WHERE CO_CD=@CO AND USE_YN='1' AND ACCT_FG IN ('0','1')
  UNION ALL SELECT '최소발주량',    COUNT(*), SUM(CASE WHEN ISNULL(LOT_QT,0)=0             THEN 1 ELSE 0 END) FROM SITEM WHERE CO_CD=@CO AND USE_YN='1' AND ACCT_FG IN ('0','1')
  UNION ALL SELECT '여신한도',      COUNT(*), SUM(CASE WHEN ISNULL(YUSIN_AM,0)=0           THEN 1 ELSE 0 END) FROM LCR_LIMIT WHERE CO_CD=@CO
) X;
```

**해석 기준**: 등록률 70% 미만이면 해당 KPI는 **개발해도 쓰이지 않습니다.** 리포트보다 마스터 정비가 먼저입니다.

#### 5차에서 특히 주의할 것

1. **A-06 의 `PJTCD_TY='D1'`** — `ADOCUD.PJT_CD` 는 `PJTCD_TY` 에 따라 프로젝트(D1)이거나
   **사원(D4)** 이다. 필터를 빠뜨리면 사원 코드가 프로젝트로 집계된다. 쿼리 E 가 유형 분포를
   먼저 보여주고, 컬럼 자체가 없는 사이트는 판정문에서 경고한다.
2. **S-11 의 `@EXP_SOFG`** — 수출 거래 구분(`SO_FG`) 기본값 `'1,3,4'` 는 **추정치**다.
   확인 쿼리로 실제 값을 확인하지 않으면 수출 건이 누락되거나 국내가 섞인다.
3. **M-07 외주비는 `LOCLS_H/D`** — `LWO_WF_D.LBR_AM`(예정치)이 아니라 마감 금액이 원가에 들어간다.
4. **P-12 LOT 추적은 기록률이 전제** — 쿼리 F 의 단계별 LOT 기록률이 낮으면 추적 결과는
   "전부"가 아니라 "기록된 것 중 일부"다. 보고서에 반드시 명시해야 한다.
5. **C-08 배부기준 변경** — 전차수와 `METHOD_FG` 가 다르면 C-03 의 전차수 대비 증감이
   무의미하다. 원가 비교 전에 쿼리 B 를 먼저 볼 것.

#### 원가 마감 전 표준 실행 순서

```
① B02_마스터점검팩.sql      ← 첫 적용 시. 코드값 해석 확정이 모든 것의 전제
② P09_재고정합성_점검.sql   ← 평가 GAP / 재공 실사 차이 해소
③ C07_원가차수_마감점검.sql ← 쿼리 A 가 '마감 가능' 이 될 때까지 반복

⑤ CIV_CHASU.CLS_YN = '1' 로 마감
⑥ C03 / C04 / C05 / E01 조회  ← 이제 '집계중' 표시가 사라진다
```

#### 상시 점검 설계상의 원칙

1. **B-02 를 가장 먼저 돌린다.** 이 산출물군 전체가 `EXPIRE_YN='1' = 진행` 전제 위에 있다.
   반대로 걸면 결과가 통째로 비어버린다(개발 중 실제로 두 번 발생). 쿼리 A 는 단순 분포가
   아니라 **"미출고 잔량이 남은 쪽이 진행"** 식으로 데이터에서 의미를 역추적한다.
2. **차단 / 경고 / 정보 3등급.** C-07 쿼리 B 는 선행 조건을 등급으로 나누고, 차단 항목이
   하나라도 있으면 '마감 불가' 로 판정한다. 등급은 회사 정책에 맞춰 조정 가능하도록 했다.
3. **점검은 찾기만 한다.** 재공조정(LWIPIO)·재고조정(LADJUST)·마스터 수정은 ERP 화면에서
   현업이 직접 해야 한다. 자동 조정 전표를 만들지 않는다.
4. **드릴다운 리포트를 항상 명시한다.** 차단 항목마다 어느 파일로 확인하는지 컬럼으로 준다.

## 8. 공통 개발 규칙

1. **`EXPIRE_YN = '1'`, `USE_YN = '1'`** 모든 트랜잭션 테이블 기본 적용
2. **행 증식 방지** — 1:N 조인은 집계 서브쿼리 또는 `OUTER APPLY (SELECT TOP 1 …)`
3. **소수점은 `SYSCFG`** — 모듈 `'S'`, 통제코드 `02`(수량)/`03`(단가)/`06`(금액), 끝전 `10`
4. **`S_CD <> 'Z00'`** (단종품) 필터 기본 적용
5. **`ACCT_FG`** 원가대상 = `('0','1','2','4','5','6')`. `SETITEM_FG` 로 세트품 분리
6. **명세서 누락 테이블은 `OBJECT_ID` 가드 + 동적 SQL** (`LWO_REQ_WF`, `LCR_LIMIT`, `CIV_*` 등)
7. **제공 뷰 우선** — `VL_*` / `LX_*` 가 있으면 원장 직접집계보다 먼저
8. **대용량 전개·집계는 야간 배치로 `LX_*` 적재** (`LX_BOM_BACK_*` 패턴)
9. **메뉴 등록은 저장프로시저 래핑** → `EXEC USP_X @@회사, @사업장, …`
   상세: `사용자정의메뉴_작성가이드.md`
