# iCUBE 리포트 사이트 적용 체크리스트

> **대상** — SQL 산출물 45개를 신규 사이트에 적용할 때
> **핵심** — [Z00_사이트진단.sql](Z00_사이트진단.sql) 하나를 먼저 돌리면 대부분 판정된다.
> 이 문서는 그 전후로 무엇을 해야 하는지의 절차다.

---

## 0. 요약 — 5단계

| 단계 | 할 일 | 산출 | 소요 |
|---|---|---|---|
| **A** | 접속·범위 확정 | DB명, 회사/사업장/연도 | 10분 |
| **B** | **진단 실행** | `Z00_사이트진단.sql` → 판정 매트릭스 | 5분 |
| **C** | **코드값 전제 확정** ★★ | 전 파일 일괄 수정 여부 결정 | 30분 |
| **D** | 파라미터 확정 | 계정코드·목표선·구분코드 | 1~2시간 |
| **E** | 순차 적용·검증 | 리포트별 결과 대사 | 1~2주 |

**D 단계를 건너뛰면 리포트가 조용히 틀린 값을 낸다.** 오류가 나지 않고 빈 결과나 0이 나오기 때문에 알아채기 어렵다. 이 문서에서 가장 주의할 부분이다.

## A. 접속·범위 확정

```sql
SELECT DB_NAME() AS DB명, @@VERSION AS 버전;
SELECT CO_CD, CO_NM FROM SCOMPANY;          -- 회사코드
SELECT CO_CD, DIV_CD, DIV_NM FROM SDIVISION; -- 사업장코드
```

확정할 값 — 45개 파일 상단 파라미터에 동일하게 들어간다.

| 파라미터 | 값 | 비고 |
|---|---|---|
| `@CO_CD` | | 회사코드 |
| `@DIV_CD` | | 사업장. 전사면 `NULL` |
| `@P_YR` | | 회계연도 |
| DB명 | | 기본 `DZICUBE` |

## B. 진단 실행

[Z00_사이트진단.sql](Z00_사이트진단.sql) 상단 파라미터만 바꿔 **전체 실행**. 읽기 전용이라 데이터를 변경하지 않는다.

### 출력 4개

| 출력 | 내용 | 보는 법 |
|---|---|---|
| [1] 진단 결과 | 5단계 검사 항목 | **치명 → 경고** 순으로 먼저 |
| [2] 테이블 실존 | 필수/선택 68종 | 필수 누락이 있으면 적용 범위 재조정 |
| **[3] 리포트 적용 판정** | 45개 파일별 O/△/X | **여기부터 보면 된다** |
| [4] 종합 판정 | 치명·경고 건수 | 다음 단계 지시 |

### 판정 읽는 법

- **O 사용가능** — 파라미터만 바꿔 바로 적용
- **△ 수정필요** — 조치 컬럼의 지시대로 파일을 고친 뒤 적용
- **X 사용불가** — 전제 테이블이 없다. 해당 모듈은 적용 범위에서 제외

## C. 코드값 전제 확정 ★★ 가장 중요

### C-1. EXPIRE_YN — 전 파일의 뿌리

45개 파일 전체가 **`EXPIRE_YN='1'` = 진행/유효**를 전제로 한다. 반대면 **결과가 통째로 비어버린다.**
개발 중 실제로 두 번 반대로 걸어 전 건이 사라진 적이 있다.

진단 2단계가 자동 판정한다 — `'1'`과 `'0'` 각각의 **미출고 잔량 비율**을 비교해 잔량이 남은 쪽을 '진행'으로 본다.

| 진단 결과 | 조치 |
|---|---|
| `'1'`잔량율 ≥ `'0'`잔량율 | 전제대로. **수정 불필요** |
| 반대 | **45개 파일의 `EXPIRE_YN` 조건을 전부 뒤집어야 한다** |

최종 확인은 ERP 화면에서 진행 중인 수주 하나를 열어 실제 값을 보는 것이다.

### C-2. DOC_ST — 작업지시 상태

API 규약(`0`미처리/`1`처리)과 UDR(`0`계획/`1`확정/`2`마감)로 갈린다.

- `2`가 있으면 → UDR 해석. M-01 기본값 그대로
- `2`가 없으면 → [M01_작업지시_진행현황.sql](M01_작업지시_진행현황.sql) **쿼리 G**로 실측 후 쿼리 A의 라벨 CASE 수정

### C-3. 그 외 코드값

진단 2단계가 모두 측정한다. 전제와 다르면 해당 리포트만 수정하면 된다.

| 코드 | 전제 | 영향 |
|---|---|---|
| `SO_FG` | 채권대상 `0,2,7` | S-04, S-06 |
| `RCPAM_FG` | `0` = 영업수금 | S-04, S-06, A-05 |
| `S_CD` | `Z00` = 단종 | 전 파일 (제외 조건) |
| `SUB_TP` / `BAD_YN` | `1` = 부산물 / 부적합 | M-01, M-02, M-06, M-11 |
| `GRP_FG` | `0`생산 `2`구매 `3`매출 `5`이동 `6`조정 | P-03, P-04, P-10 |

## D. 파라미터 확정 ★ 자동 판정 불가 — 반드시 수기 확인

진단으로 알 수 없는 사이트 고유값이다. **이걸 안 바꾸면 리포트가 조용히 틀린다.**

### D-1. 계정과목 코드 — 안 바꾸면 결과가 전부 0

```sql
SELECT ACCT_CD, ACCT_NM FROM SACCT
WHERE CO_CD='1000' AND (ACCT_NM LIKE '%외상매출%' OR ACCT_NM LIKE '%외상매입%');

SELECT LEFT(ACCT_CD,1) 앞자리, COUNT(*), MIN(ACCT_NM), MAX(ACCT_NM)
FROM SACCT WHERE CO_CD='1000' GROUP BY LEFT(ACCT_CD,1) ORDER BY 1;
```

## E. 순차 적용

### E-1. 적용 순서

```
① B-01 마스터 스코어카드        ← 다른 리포트의 신뢰도를 여기서 판단
② B-02 마스터 점검팩 쿼리 A     ← 코드값 해석 확정 (C단계와 동일)
③ 진단 출력 [3] 의 'O 사용가능' 부터 순서대로
④ '△ 수정필요' 는 조치대로 고친 뒤
⑤ 원가 리포트는 맨 마지막  ← 아래 의존 순서 참조
```

### E-2. 원가 리포트 의존 순서 ★

원가는 선행 점검을 통과해야 숫자가 의미를 갖는다.

```
B02 마스터점검팩      코드값·BOM 확정
   ↓
P09 재고정합성 점검   평가 GAP = 0, 재공 실사 차이 해소
   ↓
C07 원가차수 마감점검 쿼리 A 가 '마감 가능' 이 될 때까지 반복
   ↓
원가계산 SP 실행 (USP_COT0010_CALC_COST_TAV)
   ↓
CIV_CHASU.CLS_YN = '1' 마감
   ↓
C02 / C03 / C04 / C05 / C06 / C08 / E01 원가타일
        ← 이제 '집계중' 표시가 사라진다
```

### E-3. 리포트별 검증 — 결과가 나왔다고 끝이 아니다

각 파일에 **ERP 화면과 대사할 수 있는 쿼리**를 넣어두었다. 첫 적용 시 반드시 돌린다.

| 리포트 | 대사 방법 |
|---|---|
| S-02 주문미납 | 쿼리 G — `LSO_D.ISU_QT` vs 출고원장 합계 |
| C-04 표준원가차이 | 쿼리 G — ERP 원가 화면과 총액 대사 |
| M-04 공정별재공 | 쿼리 F — `LX_WH_W` 표준집계와 대사 |
| P-09 재고정합성 | 쿼리 B·C — 평가 전후 대사 |
| C-08 가공비배부 | 쿼리 A — 총액 3종 대사 |
| A-06 프로젝트손익 | 쿼리 D — 회계 vs 물류 대사 |

## 부록 1. 자동 대체가 동작하는 항목

아래는 테이블이 없어도 **쿼리가 죽지 않고** 대체 소스로 자동 전환된다. 어느 쪽을 썼는지 결과 컬럼에 표시된다.

| 상황 | 대체 | 표시 컬럼 |
|---|---|---|
| `VL_INVLC` 없음 | `L_INVSUM_LC` → `LINVTORY_D` → `LINVTORY` | `소스계층` (P-03) |
| `LINV_MVFIFO` 없음 | `LINVTORY` + 마스터 단가 | `소스` (P-04) |
| `LCR_LIMIT` 없음 | `STRADE.CREDIT_AM` | `한도출처` (S-06) |
| `LOPN_CRISU_CLS` 없음 | `LOPN_CRISU` | PRINT 메시지 (S-06) |
| `LEBL` 없음 | `LDELIVER` + `SO_FG` | `소스` (S-11) |
| `VL_PJT` 없음 | `LINVTORY.PJT_CD` | `소스` (P-11) |
| `CIV_PRD_TAV` 없음 | `LINV_MVFIFO` → `LINV_TAV` → `SITEM` | `원가출처` (C-05) |
