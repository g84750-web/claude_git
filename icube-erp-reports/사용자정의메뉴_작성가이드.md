**근거 (공식 매뉴얼 정본)**

- `사용자정의보고서사용법1.doc` — 텍스트 DSL (BBF4000.EXE, 2002.09.27)
- `사용자정의보고서_사용설명.txt` — DSL 확장 (입력·수정·프로시저)

## 0. 먼저 — **두 가지 체계가 있습니다**

앞서 분석한 UDR 쿼리 167건에 `:[00]` 방식과 `@@회사` 방식이 섞여 있던 이유가 이것입니다. 별개 체계입니다.

| | **A. 사용자정의메뉴** (GUI) | **B. 사용자정의보고서** (텍스트 DSL) |
|---|---|---|
| 위치 | 시스템관리 > 기초정보관리 > 사용자정의메뉴 | 별도 실행파일 `BBF4000.EXE` |
| 작성 방식 | 도구상자 드래그 + SQL설정 버튼 | 텍스트 파일에 DSL 직접 작성 |
| 파라미터 | `@라벨명` (항목 라벨이 곧 변수명) | `:[01]` (번호 기반) |
| 회사코드 | `@@회사` | `:[00]` |
| 컬럼 헤더 | 자동컬럼세팅 화면에서 입력 | `[TITLE]:` 지시어 |
| 템플릿 | 5종 (기본/연결/더블/차트/크로스탭) | 단일 리스트 |
| 입력·수정 | 불가 (조회 전용) | **가능** (`[MODIFY_*]`) |
| 프로시저 | 버튼 최대 10개 | `[PROCEDURE_*]` 3종 |

> **신규 개발은 A(GUI)를 권장**합니다. 차트·크로스탭·더블데이터 템플릿이 있고 권한관리가 표준 경로를 탑니다. B는 **데이터 입력·일괄처리 메뉴**가 필요할 때만 씁니다.

## A. 사용자정의메뉴 (GUI)

### A-1. 기본 작업순서

```
① 좌측에서 '메뉴명' 등록
② 메뉴템플릿 선택
③ [도구상자] → 조회조건 항목을 우측으로 드래그(또는 더블클릭)
④ 항목 선택 → [속성]탭에서 라벨·필수입력·도움코드·조건문 설정
⑤ 'SQL설정' 버튼 → 조회문 작성 → '쿼리실행'으로 검증
⑥ '자동컬럼세팅'에서 컬럼명 입력 + 체크 → 확인
⑦ '메뉴생성' → [모듈-분류] 지정 저장
⑧ [사용자권한설정]에서 권한 부여   ← 안 하면 메뉴가 안 보입니다
```

### A-2. 메뉴템플릿 5종 — 어떤 보고서에 무엇을 쓰나

| 템플릿 | 구성 | 적합한 보고서 |
|---|---|---|
| **기본** | 조회조건 + 데이터 | 단일 리스트 전부 |
| **연결컨트롤** | 조회조건 + 데이터 + 바인딩컨트롤 | 행 클릭 시 상세를 폼으로 보여줄 때 |
| **더블데이터** | 조회조건 + 헤더 + 디테일 | **수주→라인, 지시→자재, 품목→수불** 등 1:N |
| **차트데이터** | 조회조건 + 데이터 + 차트 | 추이·KPI (월별 수율, 매출추이) |
| **크로스탭** | 조회조건 + 크로스탭 | 월별×품목, 거래처×품목군 매트릭스 |

### A-3. 파라미터 체계

**로그인 정보 (선언 불필요)**

```
@@회사        로그인 회사코드
@@회계초일    회계 초일
@@회계말일    회계 말일
@@기수        기수          ← LINV_TAV/LINV_MVFIFO 의 GISU 와 연결
@@사업장      로그인 사원의 소속 사업장
@@부서        로그인 사원의 소속 부서
@@사원        로그인 사원코드
```

**사용자 입력 — 항목의 `라벨`이 그대로 변수명**

```sql
-- [속성] 라벨 = 사업장  →  SQL 에서 @사업장
WHERE E.CO_CD = @@회사
  AND (ISNULL(@사업장,'') = '' OR E.DIV_CD = @사업장)
```

**멀티선택 (멀티코드도움)**

```sql
AND (E.DEPT_CD IS NULL OR DATALENGTH(@부서) < 1
     OR E.DEPT_CD IN (SELECT STR_PARAMETER FROM DBO.UFN_MULTI_PARAMS_IDX(@부서)))
```

> `UFN_MULTI_PARAMS_IDX` 가 신형, `UFN_MULTI_PARAMETERS` 가 구형입니다. 사이트에 어느 쪽이 있는지 확인하십시오.

**콤보박스** — `항목`(표시값)과 `항목값`(전달값)이 다릅니다. 콤보에서 'A'를 골라도 SQL에는 `1`이 넘어갑니다.

### A-4. 도움코드 종속 관계 — `조건문` 속성

부서 도움창에 해당 사업장 부서만 뜨게 하려면:

```
[속성] 도움코드 = 부서
[속성] 조건문   = DIV_CD = @사업장
```

이 `조건문`을 빼면 전 사업장 부서가 다 나옵니다. **창고→장소, 공정→작업장, 거래처→납품처**도 동일하게 걸어야 합니다.

### A-5. 컬럼 속성 (자동컬럼세팅 화면)

**더블데이터 — 그룹여부 / 헤더여부**

| 그룹여부 | 헤더여부 | 결과 |
|---|---|---|
| 여 | 헤더 | ✓ 정상 (그룹핑 기준) |
| 부 | 디테일 | ✓ 정상 |
| 부 | 헤더 | ✗ 그룹핑 안 되어 상단에 1행만 표시 |
| 여 | 디테일 | ✗ 상단에 동일 행 중복 표시 |

**차트데이터 — 차트구분**

```
0.일반    차트와 무관, 데이터화면에만 표시
1.기준행  값을 기준행별로 순차 표시
2.기준열  기준열별로 여러 값 동시 표시
3.값      집계 대상 숫자 (수량·금액·건수). 여러 개 지정 가능
※ 값의 기준이 되는 조회기준은 반드시 하나만
```

**크로스탭 — 크로스탭구분**

```
0.일반  Y축 (행 집계기준). 여러 개 가능
1.기준  X축 (열 집계기준). 반드시 하나만
2.값    집계 숫자. 여러 개 가능
```

### A-6. 그 외 버튼

- **프로시저 설정** — 기능 하나가 버튼 하나. **최대 10개**. 일괄처리·재계산에 활용
- **인쇄설정** — 출력물 서식 지정
- **전체적용 / 선택적용** — 선택적용은 기존 컬럼 뒤에 추가됨

## B. 사용자정의보고서 (텍스트 DSL)

### B-1. 기본 제공 변수 (선언 불필요)

```
:[00]   회사코드 (자동 인식)
:[99]   회계 초일
:[GI]   회계 기수
```

### B-2. 파라미터 선언


### B-4. 출력 지시어 — 컬럼 인덱스는 **0 베이스**

```
[TITLE]:품번,품명,수량,금액;     결과 컬럼 헤더
[LENGTH]:12,30,10,12;            출력 폭
[SUM]:3,4;                       합계 표시 컬럼
[GROUP]:1;                       그룹 소계
[DATEMASK]:1;                    1번 컬럼을 20020918 → 2002/09/18
[CTR_NB_02]:3;                   수량 소수점 (SYSCFG 통제코드 02)
[CTR_NB_03]:4;                   단가 소수점 (03)
[CTR_NB_06]:5;                   금액 소수점 (06)
[REMARK]:...;                    설명
```

> `[DATEMASK]:1` 의 `1`은 **SELECT 두 번째 컬럼**입니다(0부터 셈). `[SUM]`은 1 베이스로 쓰인 사례가 섞여 있으니 실제 출력으로 확인하십시오.

### B-5. ★ 입력·수정 가능한 메뉴 (`[MODIFY_*]`)

**UDR은 조회 전용이 아닙니다.** 아래 3개를 넣으면 데이터 입력/수정/삭제 메뉴가 됩니다.

```
[MODIFY_TABLE]:LDELIVER_TEST_2;              ① 저장 대상 테이블 (필수)
[MODIFY_FIELD]:0,1,3,4,5,6,7,8;              ② 입력가능 필드 (필수)
[MODIFY_PK]:30,31;                           ③ PRIMARY KEY (필수, 없으면 수정/삭제 불가)

[MODIFY_HELP]:DT,TR_CD,,,,EXCH_CD,,,PJT_CD;  도움창 배치
[MODIFY_DEFAULT]:,,,0,0,KRW,1.000,,:[01];    디폴트값 (조회조건 :[01] 참조 가능)
[MODIFY_CALC]:,,,,,,{22}*{23},{24}+{25};     계산식 ({n}=컬럼, 0베이스)
[MODIFY_REMARK]:필수입력입니다., ,0:과세 1:영세; 컬럼별 메시지
```

**제약**
- `[MODIFY_TABLE]` 은 쿼리에 쓰인 테이블이 아니어도 됨
- `[MODIFY_CALC]` 는 MSSQL 쿼리로 계산하며 **쉼표가 들어간 식·함수 불가**
- 도움창 사용 시 **코드→명칭 자동 조회** (`CD→NM`, `NB→NM`). 단 헤더/디테일 한쪽만, 코드 컬럼 뒤 첫 명칭 컬럼에만 적용
  - 품목도움: `ITEM_NM` `ITEM_DC` `UNITMANG_DC` `UNIT_DC` 가능
  - `LOT_NB_INV`: 지원 안 함

### B-6. 프로시저 연동 3종

```
[PROCEDURE]      : SP_X( :[00], :[02] );   F11-일괄작업 버튼. 사용자가 실행
[PROCEDURE_PRE]  : SP_X( :[00], :[02] );   조회 전 자동실행 (전처리)
[PROCEDURE_POST] : SP_X( :[00], :[02] );   저장 후 자동실행 (후처리)
```

> `[PROCEDURE_POST]` 는 프로시저에서 ERROR가 나도 **저장은 이미 완료**됩니다. 롤백을 기대하지 마십시오.

## C. ★ 우리가 만든 쿼리를 메뉴에 올리는 방법

### C-1. 문제 — 현재 쿼리는 그대로 못 올립니다

지금까지 작성한 5개 쿼리는 모두 아래를 씁니다.

- 임시테이블 (`#SO`, `#COST`, `#MRP` …)
- 동적 SQL (`sp_executesql` — 테이블 존재 감지용)
- `DECLARE` 파라미터 블록
- **다중 결과셋** (쿼리 A~I)

사용자정의메뉴의 SQL설정은 **단일 SELECT 하나**를 기대합니다. 그대로 붙이면 컬럼 인식이 안 됩니다.

### C-2. 해결 — 저장프로시저로 감싸고 마지막에 SELECT 하나

```sql
CREATE PROCEDURE USP_UDR_수율현황
     @CO_CD NVARCHAR(4), @DIV_CD NVARCHAR(4)
    ,@FR_DT NVARCHAR(8), @TO_DT NVARCHAR(8)
    ,@PJT_CD NVARCHAR(10) = NULL
AS
BEGIN
    SET NOCOUNT ON;
    -- 기존 임시테이블 로직 그대로
    ...
    -- ★ 마지막에 결과셋 하나만
    SELECT ... FROM #YIELD ...;
END
```

메뉴의 SQL설정에는 한 줄만 씁니다.

```sql
EXEC USP_UDR_수율현황 @@회사, @사업장, @시작일, @종료일, @프로젝트
```

> `EXEC` 로도 자동컬럼세팅이 컬럼을 잡습니다. 안 잡히면 `SET FMTONLY` 이슈이므로 프로시저 첫 줄에 `SET NOCOUNT ON` 을 반드시 넣고, 그래도 안 되면 결과를 임시테이블에 넣고 `SELECT * FROM` 하는 형태로 바꾸십시오.

### C-3. 쿼리별 권장 템플릿 / 파라미터 매핑

| 쿼리 | 결과셋 | 권장 템플릿 | 파라미터 (라벨 → `@H()` 타입) |
|---|---|---|---|
| **PJT_생산원가_보고서** A 요약 | 프로젝트별 1행 | 기본 | 사업장`DIV_CD` / 시작일`DT_S` / 종료일`DT_E` / 프로젝트`PJT_CD` / 원가차수`CHASU` |
| 〃 B 상세 | 프로젝트×제품×자재 | **더블데이터** | 〃 (헤더=프로젝트+제품, 디테일=자재) |
| 〃 E 이상징후 | 리스트 | 기본 | 〃 |
| **생산지시별_작업수율** A | 지시별 1행 | 기본 | 사업장 / 기간 / 품목`ITEM_CD` / 공정`BASELOC_CD_1` |
| 〃 B 공정별 | 지시×공정 | **더블데이터** | 〃 |
| 〃 D 불량 Pareto | 코드별 | **차트데이터** | 〃 (기준열=불량코드, 값=불량수량) |
| 〃 G 월별 추이 | 년월×품목군 | **크로스탭** | 〃 (기준=년월, 일반=품목군, 값=양품률) |

### C-5. 다중 결과셋 처리

쿼리 A~I를 한 메뉴에 다 넣을 수 없습니다. 두 가지 방법이 있습니다.

1. **메뉴를 나눈다** (권장) — 보고서 성격이 다르므로 사용자도 나뉜 편이 편합니다
2. **구분 파라미터를 둔다** — 콤보박스 `@보고서구분`(1=요약, 2=상세, 3=이상징후)을 만들고 프로시저에서 분기. 단 컬럼 구성이 달라지면 자동컬럼세팅이 깨지므로 **컬럼 수가 비슷한 것끼리만** 묶으십시오

### C-6. 체크리스트

```
□ 프로시저 첫 줄에 SET NOCOUNT ON
□ 마지막 SELECT 하나만 남기고 중간 PRINT/SELECT 제거
□ DECLARE 파라미터 → 프로시저 인자로 승격
□ 회사코드는 @@회사 로 받기
□ 도움창 종속 조건문 설정 (창고→장소, 공정→작업장, 사업장→부서)
□ 자동컬럼세팅에서 컬럼명 한글 입력
□ [SUM] 대상 금액 컬럼 지정
□ 소수점: SYSCFG 통제코드 02(수량)/03(단가)/06(금액) 확인
□ 메뉴생성 후 [사용자권한설정] 에서 권한 부여   ← 빠뜨리기 쉬움
□ 실행 계정으로 로그인해 실제 조회 확인
```

## D. 주의사항

1. **권한 설정을 빠뜨리면 메뉴가 안 보입니다.** 메뉴생성만으로는 끝이 아닙니다.
2. **`@@기수`** 는 `LINV_TAV` / `LINV_MVFIFO` 의 `GISU` 와 대응합니다. 재고평가 관련 메뉴는 이걸 쓰면 사용자가 기수를 몰라도 됩니다.
3. **콤보박스의 표시값과 전달값이 다릅니다.** `@알파벳 = 'A'` 가 아니라 `= '1'` 입니다.
4. **`[PROCEDURE_POST]` 는 롤백되지 않습니다.** 검증 로직을 후처리에 두지 마십시오.
5. **성능** — 사용자정의메뉴는 사용자가 조건 없이 조회하기 쉽습니다. 프로시저 안에 기간 필수 체크를 넣고, 없으면 `RAISERROR` 로 막는 편이 안전합니다.
6. **구형 DSL(B)의 `[MODIFY_*]`로 만든 입력 메뉴는 ERP 표준 검증 로직을 타지 않습니다.** 재고·회계에 영향을 주는 테이블에는 쓰지 마십시오. 보조 관리 테이블에 한정할 것.

## 부록. 공식 예제 (매뉴얼 36p)

```sql
SELECT F.DIV_CD, F.DIV_NM, E.DEPT_CD, ISNULL(D.DEPT_NM,'') DEPT_NM,
       E.EMP_CD, E.KOR_NM, ISNULL(E.BRTH_DT,'') BRTH_DT, E.JOIN_DT,
       ISNULL(E.RTR_DT,'') RTR_DT,
       ISNULL(E.RSRG_ADD,'') + ISNULL(E.RSRD_ADD,'') AS ADDR
FROM        SEMP  E
LEFT  JOIN  SDEPT D ON E.DEPT_CD = D.DEPT_CD AND E.CO_CD = D.CO_CD
LEFT  JOIN  SDIV  F ON F.DIV_CD  = D.DIV_CD  AND F.CO_CD = D.CO_CD
WHERE  E.CO_CD = @@회사
  AND  E.USE_FG IN ('1','2','3','4')
  AND  (ISNULL(@사업장,'') = '' OR E.DIV_CD = @사업장)
  AND  (E.DEPT_CD IS NULL OR DATALENGTH(@부서) < 1
        OR E.DEPT_CD IN (SELECT STR_PARAMETER FROM DBO.UFN_MULTI_PARAMS_IDX(@부서)))
  AND  E.KOR_NM LIKE '%' + @사원명 + '%'
```

`SEMP.USE_FG` = 1.회사 / 2.사업장 / 3.부서 / 4.사원 (조회권한 범위)
