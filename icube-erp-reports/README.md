# iCUBE ERP 리포트 쿼리 모음

더존 iCUBE ERP(MS-SQL)의 EIS/KPI 리포트 **SQL 46개 + 진단 2개 + 참조문서 8개 + 검사 도구**.
영업·구매자재·생산·원가·회계 5개 모듈의 현황/KPI/점검 리포트.

> **상태** — 개발 완료, 정적 검사 **error 0**, **실 DB 미검증**. 실행 테스트·수정 단계.
> 검사를 통과했다는 것은 규약을 지켰다는 뜻이지, 숫자가 맞다는 뜻이 아니다.

---

## 요구 환경 — 먼저 확인할 것

**SQL Server 2012 이상이 필요하다.** 46개 중 **24개**가 2012 전용 구문
(`LAG()`, 집계 `OVER(ORDER BY …)`, `ROWS/RANGE BETWEEN` 프레임,
`PERCENTILE_CONT()`, `EOMONTH()`)을 쓴다. 2008 R2 에서는 실행 즉시 **구문 오류**가
난다 — 호환성 수준을 올려도 소용없다. 엔진 자체에 그 기능이 없기 때문이다.

어느 파일이 걸리는지는 각 파일 헤더의 `DBMS :` 줄에 적혀 있다.

```sql
SELECT SERVERPROPERTY('ProductVersion')                     AS 엔진버전   -- 11.x 이상이어야 한다
     , (SELECT compatibility_level FROM sys.databases
        WHERE database_id = DB_ID())                        AS 호환성수준  -- 90 미만이면 대부분 불가
     , SERVERPROPERTY('Edition')                            AS 에디션;
```

`Z00_사이트진단.sql` 의 **0단계**가 이것을 자동으로 판정하고, 2008 R2 면 해당
리포트를 `X 엔진버전` 으로 표시한다.

인스턴스를 옮긴다면 `Z01_인스턴스이전_점검.sql` 을 **옮기기 전 원본에서 한 번,
옮긴 뒤 대상에서 한 번** 돌려 결과를 비교한다. 이 파일은 버전을 보고 추측하지 않고
2012 구문 5종을 **실제로 실행해 보고** 되는지 판정하며, 이전 절차도 함께 들고 있다.

> **복원만 하면 끝이 아니다.** `LAG()` 등은 엔진이 2012 이상이고 **DB 호환성 수준이
> 110 이상**일 때만 동작한다. 2008 R2 의 DB 를 2017 에 복원하면 호환성 수준이 **100
> 그대로 따라오므로** 그 상태에서는 24개가 여전히 실패한다. `ALTER DATABASE … SET
> COMPATIBILITY_LEVEL` 을 반드시 함께 해야 한다.

**2008 R2 사이트라면** — 엔진을 올리거나, 2012+ 인스턴스에 리포팅용 복제본을 두고
거기서 실행한다. 후자가 대체로 낫다. 운영 DB 를 건드리지 않으므로 ERP 벤더 인증
문제가 없고, 되돌리기도 복제본을 지우면 끝이다.

## 실행 전 반드시 바꿔야 할 값

기본값이 **예시/추정치**라 그대로 쓰면 결과가 틀린다.

| 파일 | 파라미터 | 기본값 | 안 바꾸면 |
|---|---|---|---|
| B02 | `@AR_ACCT` / `@AP_ACCT` | `10800`/`25100` | 기초이관 검증 결과가 전부 0 |
| A06 | `@REV_PFX` / `@EXP_PFX` | `4` / `5,6,7,8` | 손익 구분이 틀림 |
| S11 | `@EXP_SOFG` | `1,3,4` | 수출 누락 또는 국내 혼입 |
| M07 | `@DOC_FG` | `1` | 결과가 빔 |
| M11 | `@EXP_FG` | `3` | 모의계획이 섞일 수 있음 |
| A05 | `@OPEN_CASH` | `0` | 누적잔고가 무의미 |
| C04·C05·E01·M05·S05·수주진행총괄 | `@GISU` | `NULL` (최신 기수 자동) | 자동 판정이 어긋나면 과거 기수 평가단가가 섞인다 |

상세는 [사이트적용_체크리스트.md](사이트적용_체크리스트.md) **D단계** 참조.

## 결과가 비었을 때

1. **`EXPIRE_YN`을 반대로 걸지 않았는가** — `'1'`이 진행이다. 가장 흔한 원인.
   사이트 실측 결과가 반대라면 46개를 손으로 고치지 말고 도구를 쓴다.
   ```bash
   python3 tools/flip_expire_yn.py           # 무엇이 바뀔지 미리보기
   python3 tools/flip_expire_yn.py --apply   # 반영 (두 번 돌리면 원상복구)
   ```
2. 기간 파라미터가 데이터 범위와 맞는가
3. `@DIV_CD`가 실제 사업장 코드인가 (전사는 `NULL`)
4. 구분코드 파라미터가 실측값인가
5. 해당 파일의 **마지막 쿼리(데이터 점검)**를 실행해 판정문을 읽는다
